# 2026-09-13 — Chat conversation-history feature (site-gpt)

Built full chat history feature, grouped by existing `session_id` (no new table).

## Backend
- `src/site_gpt/app/schemas/chat.py`: ConversationSummary, ConversationMessage,
  ConversationListResponse, ConversationMessagesResponse, RecentConversation,
  RecentConversationsResponse.
- `src/site_gpt/app/services/conversations.py` (new): list_conversations (GROUP BY
  session_id + first-user-msg title), get_conversation_messages, delete_conversation,
  list_recent_conversations (company-wide, joins websites for name).
- `src/site_gpt/app/api/routes.py`:
  - GET /api/conversations (manager, company-scoped) — list a website's sessions
  - GET /api/conversations/{session_id} (public, widget uses it)
  - DELETE /api/conversations/{session_id} (manager)
  - GET /api/conversations/recent (manager, company-scoped) — Dashboard preview
  NOTE: declare /recent BEFORE /{session_id} so the static path wins.

## Frontend
- types/api.ts + utils/api.ts helpers: getConversations, getConversationMessages,
  deleteConversation, getRecentConversations.
- context/ChatContext.tsx: added loadMessages.
- components/Chat.tsx: left history sidebar (New chat / select / delete), pagination
  (CONV_PAGE=20, "Load more"), deep-link `?website=<id>` preselect + `?focus=latest`
  or `?focus=<session_id>` auto-open.
- pages/Dashboard.tsx: "Conversations" stat card -> /playground?focus=latest; added
  "Recent conversations" Card (latest 5) linking to
  /playground?website=<id>&focus=<session_id>.
- scripts/widget.js: loadServerHistory() restores a session from server on init
  (fallback localStorage).

## Verified
- `uv run python -c "import site_gpt.app.main"` OK.
- `cd frontend && npx tsc --noEmit` OK; `npm run build` OK.

## Notes / limitations
- True cross-device history for end visitors needs a stable visitor identity
  (not just per-browser session_id in localStorage) — out of scope.
- Bash tool persistent cwd is the project root; `cd .../frontend &&` is needed
  before `npm` commands (a bare `npm run build` runs in the wrong dir).
