## Chat SSE error (ERR_INCOMPLETE_CHUNKED_ENCODING)
- Symptom: `POST /api/chat/stream` failed in browser with `net::ERR_INCOMPLETE_CHUNKED_ENCODING 200 (OK)` / "Chat stream error TypeError: network error".
- Root cause: `ask_stream` (rag.py) raised an exception inside the async generator (embedding API call), so FastAPI closed the chunked response before the final terminator chunk → browser sees a truncated stream.
- Fix (symptom): wrapped `ask_stream` in try/except; on any error it now yields `data: {"error": <short msg>}` then `data: {"done": true}`, logging full traceback server-side. Both clients (`frontend/src/context/ChatContext.tsx`, `src/site_gpt/app/scripts/widget.js`) now parse the `error` event and render it instead of throwing.
- Underlying blocker (config): `.env` has `LLM_AI=custom_openai`, `LLM_MODEL=auto`, `LLM_EMBEDDING_MODEL=auto` with `OPENAI_API_BASE_URL=http://127.0.0.1:31415/v1`. `auto` is not a valid model → embedding call returns 400 (`input is required`). RAG can't run until a real 1536-dim embedding model is set (the `embeddings` column is `Vector(1536)`). Left `.env` untouched — needs the user's real model name.
- Verified: `py_compile` of rag.py OK; simulated `ask_stream` error path yields 2 events (`error` + `done`) and does NOT raise; `frontend tsc --noEmit` exit 0.

## Chat streaming fixed (root cause + two more bugs)
After the symptom fix, dug into why chat still couldn't answer. Diagnosed via probing the live gateway at `OPENAI_API_BASE_URL=http://127.0.0.1:31415/v1` (283 models).
- LangChain `OpenAIEmbeddings` wrapper fails against this gateway (`400 input is required`) even though the raw OpenAI SDK works. Replaced it with a thin `_OpenAICompatibleEmbeddings` class in `services/llm.py` that calls `openai.OpenAI(...).embeddings.create` directly.
- Gateway `/embeddings` only accepts `model: auto`; `auto` returns **3072-dim** vectors, but `embeddings.embedding` is `Vector(1536)`. Gateway honors OpenAI `dimensions` param, so we request `dimensions=1536` (for `auto` / `text-embedding-3-*`) → 1536-dim vectors, **no schema change needed**.
- Second bug: `ask_stream` passed `embed_texts([question])` (list-of-lists) into `search()` without the `[0]` unpack that the sync `ask()` does. `search()` then serialized it as `[[...]]` → pgvector `invalid input syntax for type vector`. Fixed by unpacking `[0]` in `ask_stream`.
- Verified end-to-end: `embed_texts` → 1536-dim; `get_llm().invoke` works; `ask_stream` over a real website yields `chunk` events + `done` (LLM answers from context). `py_compile` + `import site_gpt.app.main` OK.
- Note: embeddings were failing before, so no vectors were stored. User must (re-)ingest/crawl a website now that embeddings work for the bot to have knowledge.
