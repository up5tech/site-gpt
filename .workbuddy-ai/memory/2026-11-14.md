(code-verified via graft graph + targeted greps, not just README).

## Created plans/SPEC.md

Wrote a code-grounded implementation spec for closing those gaps (802 lines,
English, matching repo doc conventions). Key decisions:

- **Real bug found**: `services/mail.py::send_email` calls
  `FastMail.send_message()` without awaiting it (verified in venv: it is
  `async def`) — no email is ever sent, incl. password reset. Phase 0 blocker.
- **Security prerequisite**: `GET /api/widget-config` is public and returns ALL
  `settings` rows; must become an explicit allowlist before adding ~14 new keys.
- `api/setting.py` duplicates default keys in two places → unify into one
  `DEFAULT_SETTINGS` first.
- Q&A training reuses a synthetic `ExtraDocument` (`__qa_training__`) +
  `ingest_extra_document`, avoiding a third FK on `embeddings` and any change to
  `rag.py::search` or `EMBEDDING_DIMENSIONS` (no re-ingest needed).
- Digest rides the existing `worker.py` Redis queue (`{"type":"digest"}`) with a
  `digest_log` unique constraint for idempotency; `chat_messages.answered` flag
  identifies unanswered questions instead of string-matching LLM output.
- 10 features F1–F10 across 5 phases, 5 migrations M1–M5, all opt-in/off by
  default. Certifications, trial/pricing stay explicitly out of scope.
